# brain-cmdb

A lightweight, note-native CMDB over the existing `vault/devices/` (machines/hosts)
and `vault/integrations/` (services/endpoints) notes. Configuration Items (CIs) are
those notes; relationships are three typed frontmatter list fields:

- `hosted_on: [<host-slug>]` — this CI runs on that host.
- `depends_on: [<ci-slug>]` — needs these CIs to function.
- `provides: [<ci-slug>]` — CIs this one serves.

Frontmatter is authoritative; `## Relations` (wiki-links) is generated by `sync`.

## Usage

```
brain-cmdb [--space <slug>] list          # every CI (devices + integrations + opted-in projects)
brain-cmdb register <ci>                   # mint/print a CI's stable ci- id (opt a project in)
brain-cmdb register --backfill             # mint ci- ids for every device + integration
brain-cmdb show <ci>                       # a CI + its three relation fields
brain-cmdb runs-on <host>                  # CIs with hosted_on: <host>
brain-cmdb what-depends-on <ci>            # reverse deps ("if <ci> is down, what breaks?")
brain-cmdb provides <ci>                   # CIs that list <ci> under provides
brain-cmdb resolve <ci|ci-id>              # slug -> path, or ci-id -> slug
brain-cmdb rename <old> <new>              # rename a CI + rewrite referrers (ci- id preserved)
brain-cmdb sync                            # regenerate every CI's ## Relations from frontmatter
```

CI data is private — the bin reads `${AGENTBRAIN_LOCAL_DIR:-~/agentBrain/local}`.

## Identity, projects, and spaces

- Each CI carries a stable `ci: ci-XXXXXXXX` id (minted once, survives renames — unlike
  the path-derived vault `id`). It is the CI marker, its durable identity, and its search
  handle. Devices/integrations get one via `register --backfill`; a **project** becomes a
  CI when you `register <project>` it.
- **Relations stay slug-based** in frontmatter (`depends_on: [gitea]`) — readable and
  hand-editable. `rename` handles the rare slug change.
- **Spaces:** the CI root follows the active space context (`--space <slug>`,
  `AGENTBRAIN_CONTEXT`, or `system/lib/context.sh` inference), so a client's CIs stay
  sealed in `vault/spaces/<slug>/` and never leak across a boundary.

## Coverage

Run `bash scripts/checks/check-cmdb-coverage.sh` (advisory) to find real infrastructure
with no CI, or CIs with no relationships.
